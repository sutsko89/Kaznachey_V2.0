# Казначей

Однопользовательское десктоп-приложение для учёта личных финансов.
Работает полностью офлайн, не требует входа, регистрации, ПИН-кода или пароля.
Данные хранятся локально в одном файле SQLite (`kaznachei.db`).

## Возможности

- Учёт доходов и расходов с категориями, месячными лимитами и шаблонами;
- Поиск (регистронезависимый, по подстроке описания и имени категории) и совместные фильтры (период, тип, категория);
- Сводка за период, отчёт по категориям, контроль превышения лимитов (красная подсветка);
- Пагинация и сортировка таблицы операций;
- Экспорт операций в CSV (UTF-8 с BOM, разделитель `;;`, учитывает текущие фильтры, шаблоны не экспортируются);
- Мультивалютность как информационный тег (RUB / USD / EUR / произвольный код), расчёты в базовой валюте, автоконвертация не выполняется;
- Резервное копирование в один клик и ручной откат к бэкапу из настроек с подтверждением;
- Миграции схемы БД (папка `migrations/`, нумерация `001_init.sql`…), автоматический бэкап перед каждой миграцией, откат транзакции при ошибке;
- Защита от запуска второго экземпляра на ту же базу («Приложение уже открыто»);
- Русский интерфейс, форматы: числа `12 345,67`, даты в UI `DD.MM.YYYY`, в БД `YYYY-MM-DD`;
- Светлая/тёмная темы, масштаб интерфейса (100/125/150 %), размер страницы (25/50).

Сетевые запросы, телеметрия и облачная синхронизация отсутствуют.
Модуль безопасности (ПИН, пароль, сессии, блокировки) в этой редакции **не предусмотрен**.

## Требования

- Windows 10 / 11 x64 (либо любая ОС с Python для разработки);
- Python 3.11+;
- Зависимости из `requirements.txt`.

## Установка и запуск

```bash
python -m venv .venv
.venv\Scripts\activate            # Windows (Linux/macOS: source .venv/bin/activate)
pip install -r requirements.txt
python main.py
```

При первом запуске создаётся база `kaznachei.db` и применяются все миграции.

## Горячие клавиши

| Клавиша | Действие |
|---|---|
| Ctrl+N | добавить операцию |
| Ctrl+F | фокус на строку поиска |
| Ctrl+E | экспорт в CSV |
| Ctrl+B | создать бэкап |
| Ctrl+1…4 | вкладки: Операции / Бюджеты и категории / Шаблоны / Настройки |
| Enter | сохранить в диалоге |
| Esc | закрыть диалог без сохранения |

## Архитектура

```
main.py                  — точка входа (запуск без экрана входа)
app/
  main.py                — инициализация QApplication, single-instance, главное окно
  dal/database.py        — слой доступа к данным: SQLite, транзакции, CRUD, поиск, пагинация
  domain/service.py      — бизнес-логика: операции, шаблоны, балансы, лимиты, настройки
  domain/validators.py   — валидация (сумма > 0, дата YYYY-MM-DD, категория обязательна)
  services/migrations.py — применение SQL-миграций + бэкап перед каждой миграцией
  services/backup.py     — создание бэкапов и восстановление (откат)
  services/export.py     — CSV-экспорт (UTF-8 BOM, разделитель ;;)
  ui/                    — главное окно, вкладки, диалоги
migrations/              — SQL-скрипты: 001_init.sql, 002_add_limits.sql, …
tests/                   — pytest: unit, интеграционные, производительности, UI (pytest-qt)
```

### Модель данных (основное)

- `categories(id, name, type income|expense, is_active, monthly_limit, created_at)` — уникальный `(name, type)`; `monthly_limit = 0` означает «без лимита», для доходов лимит не применяется;
- `transactions(id, type, amount, category_id, date, description, currency, is_template, created_at, updated_at)` — `is_template = 1` помечает шаблон: он не попадает в ленту операций, балансы, лимиты и экспорт;
- `app_settings(key, value)` — разрешённые ключи: `base_currency`, `db_version`, `date_format`, `number_format`, `ui_scale`, `theme`, `page_size`, `backup_path`; хранение любых ключей авторизации запрещено;
- `schema_version(version, applied_at)` — таблица версий схемы.

## Тесты

```bash
QT_QPA_PLATFORM=offscreen python -m pytest        # все тесты (UI — в offscreen-режиме)
```

Покрытие: DAL, миграции (включая откат при ошибке и бэкап перед миграцией),
доменная логика, бэкапы/экспорт, интеграционный сценарий (ТЗ 7.2),
производительность (10 000 операций: поиск/фильтрация < 0,5 с, старт < 3 с) и UI-тесты.
Результаты замеров фиксируются в `perf_report.txt` (генерируется тестами производительности).

## Сборка exe (Windows)

```bash
pyinstaller kaznachei.spec
```

Готовый файл: `dist/kaznachei.exe`. Рядом с ним разместите папку `migrations/`
(по ТЗ она лежит рядом с исполняемым файлом). Установка Python не требуется,
права администратора не нужны; данные можно хранить в пользовательском каталоге
и переносить вместе с папкой на другой компьютер.

## Резервные копии и откат

- Имя бэкапа: `kaznachei_backup_YYYYMMDD_HHMMSS_v<текущая_версия>.db`;
- Перед каждой миграцией бэкап создаётся автоматически; если бэкап создать не удалось — миграция не выполняется;
- Откат: Настройки → «Резервные копии и откат» → выбрать бэкап → «Восстановить» → подтвердить. Текущая БД переименовывается в `kaznachei_old_<timestamp>.db`, бэкап копируется на её место, приложение закрывается; при следующем запуске применятся необходимые миграции.
